**Status:** proposal — awaiting the owner's approval.

## Where snes9x-wasm stands (0.1.1)

- Legacy contract: `load(config)` → `EngineInstance`, engine-specs `^0.2.4` (ROADMAP: ❌ 1.0).
- Already there, and enough for the app: `saveState()` / `loadState(bytes)` (the shim's
  `_s9xwasm_state_*`), `pause()` / `resume()`, SRAM in OPFS `snes9x/<namespace>/sram.bin`,
  a 2D canvas (so a frame can be read back), gamepads read from `navigator.getGamepads()` with
  the SNES mapping by position (B 0, A 1, Y 2, X 3, L 4, R 5, Select 8, Start 9) — exactly engine-specs'
  `TOUCH_LAYOUTS.snes`, so the touch pad plays it as it is.
- Its own Escape settings overlay (`snes9x.menu.ts`), which would fight the app's pause menu.

No wasm change is needed: everything below is TypeScript and the app.

## Plan

1. **Contract 1.0** — `Snes9xSDK` / `Snes9xPlay` on engine-specs' `EngineSDKBase` /
   `EnginePlayBase` (`options / assets / storage / mount / start`, `pause(owner)`,
   `restart()`, `destroy()`, events), as blastem-wasm did in its 1.0 record; the engine-specs
   runtime copied beside the SDK (self-contained ESM, no import map); `storagePath()` →
   `snes9x/<namespace>/`. `load()` goes (breaking → minor release).
2. **Save-state slots** — `play.states` with blastem's shape: `list()` (slots 0-3), `get(9)`
   (the unsaved point), `save(slot, { thumbnail })`, `load(slot)`, `copy(from, to)`,
   `lock(slot, on)`, `remove(slot)`; files `slot_N.state`, `slot_N.png`, `slot_N.lock` in the
   OPFS folder; `play.snapshot()` (the canvas as PNG).
3. **The engine app** — `app/app.js` + `app.css`: blastem's app on this SDK (`s9x-` classes):
   suspend points, the pause menu with the four slots (Cargar focused), menus by touch. Through
   the app the Escape settings overlay is off (`escMenu: false`); the settings stay reachable
   for hosts without the app.
4. **Pinned build** — check that the build pins upstream and that its patches fail loudly.
5. **Launcher** (play.germade, its own record): `engines.json` gains snes9x; the catalog's SNES
   entry runs on it (decision below).

## Verify

`make test` (+ new tests for the states API against a fake module); end to end in Chromium as a
phone with the touch pad and a blank SNES ROM (the menus are the app's), and a real game on the
owner's device.

## Decision for the owner

The launcher's SNES entry says `engine: 'jgenesis'` (status "soon"). Recommended: **snes9x as the
SNES core** (mature, no WebGPU, verifiable here), jgenesis as a second core, like Mega Drive has
BlastEm + jgenesis.
